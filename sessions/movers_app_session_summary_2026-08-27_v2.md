# What shipped (all on main at 5258490)

- **F11(d) — References chain accumulation. DONE (PR #67, baf6fc5).** sending.ts was setting both In-Reply-To and References to the single inbound Message-ID, so the chain never grew and strict clients (IONOS/Hostinger) dropped the thread head two hops in. Fix: References = the inbound run's stored `references_header` (banked by S202) + the inbound Message-ID appended, deduped; In-Reply-To stays the single parent. **No migration** — S202 already added and populated `references_header`, which was F11(d)'s old blocker, so this became code-only. Two files: sending.ts (the header build) + actions.ts (loader select + both send call-sites pass `references`). **Verified on real email at hop-1** (single id, correct). The accumulation branch (References longer than In-Reply-To) is NOT reachable from the live queue — S202 escalates every threaded inbound before it can draft — so it gets its real exercise when the writeback send-in-thread path runs. Shipped on that basis, same precedent as S198's untested abort branch.

- **F15 writeback slice — built as three units, model A (Responded + Escalated feed).** Folder model chosen = **A** (two piles: handled → Responded, needs-human → Escalated feed), over B (Responded-only, escalations stay in INBOX). Folder names locked as **`INBOX.MoversApp Responded`** / **`INBOX.MoversApp Escalated`** — space-nested under INBOX, delimiter discovered per-server (Cornwall uses `.`), never hardcoded.

  - **Unit 1 — lib ops (PR #68, 1c50cf4).** `ensureWritebackFolders` (idempotent create, tolerates already-exists) + `moveMessageByUid` (RW open, search-for-uid then `messageMove`, absent = no-op, never creates its destination) in lib/mailbox/imap.ts, plus a throwaway `scripts/writeback-smoke.ts`. **Verified end-to-end against Cornwall's real Hostinger mailbox** via the smoke script: 3 folders created, idempotent second call (Hostinger returns `created:false`, does NOT throw ALREADYEXISTS), UID moved, second move returned absent. Read-only ops (verify/sync/fetch) untouched — the `-42` in the diff was insertion churn, confirmed.

  - **Unit 2 — wiring (PR #69, 68db38f; build-fix PR #70, 319a7a8).** After a successful manual send, for `source='mailbox'` runs on a connected mailbox: append the reply to the tenant's Sent folder (`\Sent` special-use discovery, nodemailer MailComposer builds the raw RFC822), move the original to Responded with `\Answered`, and drop the S190 BCC **conditionally** (kept for non-mailbox / no-connected-mailbox / null-message_id runs, dropped only where Sent-append covers the record). Order: send → rows to `sent` → then writeback, each step in its own catch, never throws up to the caller (a writeback failure cannot break or reverse a delivered reply). sending.ts refactored to shared exports (`buildReplyThreadHeaders`, `buildReplyEmailHtml`) so the Sent copy threads identically to the real send — **F11(d) References logic confirmed byte-identical after the refactor**. Schema fact established: `agent_runs` has **no UID column** — only `message_id` (text, nullable) + `source` (not-null); 0 null message_ids across all 334 live runs. So the move locates by Message-ID, not UID. **PR #70** fixed the build: nodemailer was imported with `require()`, which `npm run build`'s ESLint (`@typescript-eslint/no-require-imports`) rejects — converted to a static ESM import. nodemailer + @types/nodemailer added to package.json.

  - **Unit 3 — folder provisioning (PR #71, 5258490).** `ensureTenantWritebackFolders` discovers the INBOX delimiter, creates the two MoversApp folders, persists paths to `tenant_mailboxes.replied_folder` / `escalated_folder`, returns them. Wired at connect (new tenants) and as a backfill inside `performMailboxWriteback` (existing tenants self-heal on first eligible send). Move now reads the stored `replied_folder` instead of the hardcoded string.
